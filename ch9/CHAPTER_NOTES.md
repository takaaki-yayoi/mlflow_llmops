# 第9章だけサンプルコードがノートブック (.ipynb) 形式である理由

本リポジトリは 3〜8 章は `.py` ファイル + `make` コマンド形式 (バッチ実行向け) ですが、第9章だけは `.ipynb` 形式を採用しています。理由は次のとおりです。

- **対話的な試行錯誤に向いた章である**: 9.1 (情報抽出)、9.2 (エージェント型 RAG)、9.3 (マルチエージェント) はいずれも、各セルの出力を見ながら次の手を決める「インクリメンタルな実装」を体験する章です。`.py` で一括実行するより、セル単位で結果を確認しながら進めるほうが学びが深いと判断しました。
- **MLflow UI と並べて見る前提**: 各セルで MLflow にログを残し、UI 側で結果を眺めながら次のセルに進む流れになります。Jupyter のセル実行と MLflow UI の交互参照が自然に成立します。
- **`%pip install` セルで依存を完結できる**: 9.2 / 9.3 はそれぞれ章固有の依存 (`chromadb`、`litellm` 等) を必要としますが、ノートブック冒頭の `%pip install` セルでその場で導入できる構造にしています。`.py` + `pyproject.toml` 形式だと章ごとに環境を分ける必要があり、チュートリアル目的だとオーバーヘッドが大きくなります。
- **写経して動かすより「読み解く」を主眼**: 9 章の 3 テーマは実装規模が大きく、セルを順に実行しながら出力を確認するほうが、本書の「チュートリアル」章としての位置付けに合います。

なお、ノートブック形式が苦手な場合や CI で実行したい場合は、本リポジトリの CI で nbformat による静的検証を行っています ([.github/workflows/ci.yml](../.github/workflows/ci.yml))。実行は手元で行ってください。

# 共通の前提条件

- Python 3.11 以上
- OpenAI API キー
- 各ノートブック内の `YOUR_API_KEY` を実際のキーに置き換えてください。
- MLflow Tracking Server をローカルで起動しておく必要があります。

```bash
uv run --prerelease allow mlflow server --host 0.0.0.0 --port 5000
```

ブラウザでは `http://localhost:5000` でアクセスしてください (`0.0.0.0` ではアクセスできない場合があります)。
