# 第9章 チュートリアル — なぜこの章が必要か

# どんな現場課題に効くか

3〜8 章までで MLflow GenAI の各機能を個別に学んできましたが、実プロジェクトでは「文書情報抽出を構築したい」「エージェント型 RAG を立ち上げたい」「複数の専門エージェントを協調させたい」のように、**複数の機能を組み合わせた実装パターン**が必要になります。本章は 3 つの代表的なシナリオを通して、これまで学んだ機能を統合する実例を示します。Prompt Registry + Models from Code + サービング + 評価、を一気通貫で動かす場面を体感できます。

# 使わないとどうなるか

3〜8 章を学んだだけだと、「機能の単品は理解したけれど、自分のプロジェクトでどう組み合わせるか」のイメージが湧かない、という状態になりやすいです。星 5 のレビューが「読み終わる頃には自分たちが今後組むべき基盤の輪郭がはっきり見えていた」と書いているのは、本章のような統合例があるからこそ得られる感覚です。本章を飛ばすと、各章の機能が「便利そうだが、結局どう繋ぐか」のままで終わりがちです。

# 9.1 文書情報抽出モデルの構築

Prompt Registry でプロンプトを登録 → Models from Code で推論ロジックを登録 → エイリアスで本番化 → サービング → コスト集計、の流れを 1 つのノートブックで体験できます。「LLM をベースにした地味な業務処理 (請求書からの項目抽出、契約書の要約等) を本番に乗せる」シナリオの典型例です。

# 9.2 エージェント型 RAG システム

ベクトル DB (Chroma) + LangGraph で動的にツールを呼び分けるエージェントを構築し、`mlflow.genai.evaluate` で評価する例です。RAG の中でも「単純な検索 → 回答」ではなく、「足りなければ別ソースを探す」「自信が無ければユーザに聞き返す」のような分岐があるケースを扱えるようになります。

# 9.3 スーパーバイザー型マルチエージェント

複数の専門エージェントを 1 つの ResponsesAgent の背後に置く設計パターンを実装します。Safety / Guidelines / カスタムスコアラー / Agent-as-a-Judge の評価手法を通しで適用するため、評価機能の応用編としても価値があります。

# 本書の該当節と一緒に読むと良い箇所

- 本章の 3 つのチュートリアルは独立しています。自分のユースケースに近いものから読み始めて構いません。
- ノートブック形式を採用している理由は [ch9/CHAPTER_NOTES.md](../../ch9/CHAPTER_NOTES.md) 冒頭を参照してください。対話的に試行錯誤するのに向いた章である点が、3〜8 章とのスタイル差になっています。
- 本章のコードはサイズが大きいため、最初は「写経して動かす」よりも「セルを順に実行して、各セルで何が起きているかを MLflow UI で確認する」アプローチが効率的です。
