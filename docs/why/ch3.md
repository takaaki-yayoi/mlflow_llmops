# 第3章 MLflowのインストールと初期設定 — なぜこの章が必要か

# どんな現場課題に効くか

LLMOps の各手法は「何かしら動いているアプリケーション」がなければ試せません。本章は、第4章以降でトレーシング・評価・プロンプト管理を 1 つずつ足していくための土台として、**MLflow をいっさい使わない「素の」QA エージェント**をまず手元で動かす章です。同時に、uv による再現可能な Python 環境、`.env` による秘密情報の分離、`Makefile` によるコマンドの統一、ローカルの MLflow Tracking Server の起動といった、後続章で毎回使う足回りをここで一度に整えます。

現場で最初に詰まるのは、たいてい LLM のロジックそのものではなく「同僚の環境で動かない」「API キーがコードに埋まっている」「ベクトル DB のサーバを立てるところで力尽きる」といった周辺の問題です。本章のサンプルは、`uv sync` で同一環境を再現し、`.env.template` をコピーするだけでキー管理が済み、Milvus Lite でサーバなしにベクトル検索が動く構成になっているため、この手の摩擦を最小化した状態で先に進めます。

# 使わないとどうなるか

MLflow なしの状態を一度動かしておかないと、第4章で「4 行足しただけでこれだけ見える」という差分の大きさが実感できません。また、LLM プロバイダーの切り替え (3.4 節) や Tracking Server の構成 (3.5 節)、マネージド MLflow の選択肢 (3.6 節) は、後から必要になったときに戻ってきて参照する内容です。本章を飛ばして自己流の環境で第4章以降を始めると、章ごとのサンプルコードが前提にしているディレクトリ構成や環境変数と食い違い、本書の説明とリポジトリの挙動が一致しなくなります。

# 本書の該当節と一緒に読むと良い箇所

- 本書はセットアップ手順と処理フロー (図3.1) の説明が中心で、エージェント本体のコードは掲載していません。`ch3/agents/langgraph/agent.py` を読みながら LangGraph 公式ドキュメントの State と Memory のセクションを併読すると、`StateGraph` / `ToolNode` / `MemorySaver` がどう組み合わさっているかが把握しやすくなります。
- 本章単独だとトレーシングの恩恵が見えないため、まず ch3 で動かしたあと、すぐ ch4 に進んで MLflow UI でトレースを眺めるのがおすすめです。
- 3.4 節でチャット用モデルを OpenAI 以外に切り替える場合、埋め込みモデルは OpenAI のままになる点に注意してください。詳細は [ch3/CHAPTER_NOTES.md](../../ch3/CHAPTER_NOTES.md) の 3.4 節の項を参照してください。
